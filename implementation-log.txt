## done
- mixHue follows the direction the user asked for (signed delta c1.h -> c2.h),
  not the long or short arc — swapping c1/c2 reverses the trace. t already
  oscillates 0->1->0 via sin in pencilColor, so the trace cycles c1 -> c2 -> c1
  along that exact direction.
- whole mode now shares the same math: added oscT(progress, animSpeed) helper
  (= 0.5-0.5*cos(2*pi*f), identical sine bump to pencilColor's 0.5+0.5*sin) and
  use it in computeWhole + recolorWhole in place of the linear ramp. animSpeed
  still scales how many forward+back cycles fit in one closed period; seam now
  closes (t=0 at both ends), so the ring flows color1 -> color2 -> color1
  along the same single arc as animate mode.
- added per-pencil animMode ('frequency' | 'cycles', default 'frequency') toggle:
  - 'cycles': 0->1->0 cosine bump (color1-color2 and back), 1 bump per 1/animSpeed
    seconds in animate mode; cycles-per-period in whole mode (via oscT).
  - 'frequency': sawtooth frac(time*animSpeed) - hue advances linearly then wraps
    (hue-per-tick ramp); no continuous muddy sine.
  Slider max raised 0->2 to 0->4 (up to 4 hue cycles). Whole mode always uses
  the cycles arc math (its natural meaning) regardless of animMode.
- GUI: mode is now a pair of .btn toggle buttons ('cycles' / 'frequency',
  .active on selected) instead of a dropdown; slider prefix relabels to
  'cycles ' / 'hue/sec '. Toggle triggers onGearParam(gear,'color').

## _0.6 text below kept for history_

- js/camera3.js (new, pure/node-guarded): mat4 lookAt/perspective/multiply
  (row-major), orbit camera state {yaw,pitch,dist,target}, viewProj,
  projectPoint (top-left-origin screen pixels, behind-near flagged + clamped),
  orbitBy (pitch clamped to +-89deg, yaw wraps), dolly (exp scale clamped to
  [0.05R,40R]), panBy (distance-scaled camera-plane pan), fitDist,
  sanitizeCamera, lerpCam (fit ease).
- gear.js: per-point phaseRing (parallel Float32Array allocated/copied by
  reallocRing, written by pushPoint(gear,x,y,col,phase)); update/sampleAt take
  rootRot (root's own rot is the spin clock, cached on gear._rrot);
  detectPeriod(roots, maxTurns, tol, spinK) adds the plane-azimuth closure
  harmonic |spinK*root.speed| per root so the baked 3D figure closes in
  (x,y,z). 2D callers pass 0 -> byte-identical behavior.
- render.js: R.depth(on) (DEPTH_TEST/depthMask); begin() disables depth and
  clears it for the 2D path; the overlay FBO gets a DEPTH_COMPONENT24
  renderbuffer (recreated in overlayResize, cleared in overlay.clear).
- main.js: App.dim/spinSpeed/cam/autoRotate; planeTo3D/projectRing project
  the trail into a reused projScratch (CAP*5) fed to the unchanged 2D draw
  loops through a scratch gear under pushIdentity/popIdentity (no per-frame

  depth on for the trail and projected skeleton circles / dial / axes / pen

  eased fit/reset camera; setDim/setSpinSpeed (snaps in whole mode)/
  setAutoRotate/fitView; pointer split (left-drag orbit, right/mid + 2-finger

  centers; GESTURE_SEG_BUDGET_3D (projection cost); scene dim/spinSpeed/camera
  saved top-level and restored on load (applyScene3D); reset returns to 2D.
- gui.js: 2D/3D button pair + setDim; 3D panel section (spin speed,
  auto-rotate, fit/reset camera) hidden in 2D with dim-specific help; spin row
  becomes the discrete valid-position index slider in whole mode
